### Architecture Pattern
- **Primary Pattern:** Decoupled SPA (Single Page Application) + REST API. Backend interacts closely with Docker socket (`/var/run/docker.sock`).
- **Module Boundaries:** Feature-driven folders in backend (e.g., `api/routers/apps.py`, `api/db/crud/apps.py`), UI views/components in frontend.
- **Monorepo / Polyrepo:** Yes (Monorepo-style structure, split between `/frontend` and `/backend`). Tooling: Vite for frontend build, python/uvicorn for backend.

### Data Flow (Traced End-to-End)
1. **Request Entry:** Nginx reverse proxy redirects `/api/*` requests to FastAPI backend on `127.0.0.1:8000` (no trailing slash).
2. **Routing Layer:** FastAPI endpoints in `backend/api/routers/*.py` handle incoming requests.
3. **Business Logic Layer:** Shared between routers and dedicated modules like `backend/api/actions/*.py` or CRUD helpers `backend/api/db/crud/*.py`.
4. **Data Access Layer:** SQLAlchemy ORM interacting with SQLite via `SessionLocal()`. Heavy reliance on `pydantic` schemas for validation. Some state is pulled directly from the Docker daemon using `aiodocker` or `docker`.
5. **Response/Output:** JSON serialized through Pydantic models. Errors are raised as FastAPI `HTTPException`.

### State Management
- **Pattern:** Transitioning from Vuex to Pinia. Vuex is still heavily used for Auth and overarching state, while new stores are written in Pinia (`src/stores/authStore.js`).
- **Rule:** Avoid redundant network requests by using local state (e.g., `store.state.apps.apps`) when building search components or lists, unless querying external data.
- **Store location:** `frontend/src/store/` (Vuex), `frontend/src/stores/` (Pinia).
- 🔴 **Inconsistency found:** Both Vuex (`auth.js`) and Pinia (`authStore.js`) exist for authentication state. Vuex appears to be the primarily wired one in `router/index.js`.

### Data Fetching
- **Pattern:** Axios is the primary HTTP client.
- **Rule:** A global Axios interceptor handles 401 Unauthorized responses by attempting a token refresh.
- **Rule:** Independent API requests during initial loading must be executed concurrently using `Promise.all()` to minimize wait times.
- **Server-side:** Synchronous DB calls within async FastAPI endpoints must be wrapped in `fastapi.concurrency.run_in_threadpool` to avoid event-loop starvation. External requests should run concurrently with synchronous DB calls.

### Error Handling
- **Client errors:** Axios interceptors catch global errors. Components should catch local errors and trigger notifications via `this.notify()` or `$notify`.
- **Server errors:** Backend raises FastAPI `HTTPException`. Database updates violating unique constraints must catch exceptions, execute `db.rollback()`, and raise a 400 `HTTPException`.

### Authentication & Authorization
- **Mechanism:** JWT-based authentication.
- **Session access pattern:**
  - Backend: Uses `Depends(get_auth_wrapper)` and `.jwt_required()`. Setup endpoints use `allow_setup_pending=True`.
  - Frontend: Vue Router `beforeEach` guard checks `store.state.auth.status` and `store.getters["auth/isAuthenticated"]`.
- **Security Check:** Endpoints verify user permissions (e.g., `perm_start`, `perm_restart`) against the database.
- **IP Restriction:** Login routes use `check_ip_restriction` to block non-private IPs by default.
- **Timing Attacks:** Password verification uses a unified path, testing against a real hash or a static `DUMMY_HASH` to prevent user enumeration.

### Styling
- **Primary system:** Vuetify 3 (Material Design).
- **Rule:** Dialog action buttons (`<v-card-actions>`) should consistently use the `text` attribute for 'Cancel' and semantic colors (e.g., `color="error"`) for destructive 'Continue' buttons.
- **Accessibility:** Icon-only buttons (`<v-btn icon>`) must include `aria-label` and `title`.
