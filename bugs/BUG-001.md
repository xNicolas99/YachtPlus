1. Zusammenfassung (2–3 Sätze)

The `update_user` function allows a user to update their username to an existing username (due to casefold or lack of uniqueness check before commit), potentially leading to an authorization bypass or taking over another account.

2. Betroffene Stellen
Datei | Zeile(n) | Rolle

backend/api/db/crud/users.py | 68 | update_user_by_id

3. Code-Snippet (eingebettet)

```python
// backend/api/db/crud/users.py:34-58
def update_user(db: Session, user: schemas.UserUpdate, current_user):
    _hashed_password = get_password_hash(user.password) if user.password else None
    _user = get_user_by_name(db=db, username=current_user)

    if _user and _user.is_active:
        if user.username and _user.username.casefold() != user.username.casefold():
            print("Old Username: {name}".format(name=_user.username))
            print("New Username: {name}".format(name=user.username))
            _user.username = user.username.casefold()

        if user.password:
            _user.hashed_password = _hashed_password

        try:
            db.add(_user)
            db.commit()
            db.refresh(_user)
        except Exception as exc:
            raise HTTPException(status_code=400, detail=exc)
        return _user
```

4. Erwartetes Verhalten

The update should fail with a clean error message (e.g., 409 Conflict) if the new username is already taken, preventing an IntegrityError or account takeover.

5. Tatsächliches Verhalten

If a user updates their username to one that already exists, the database raises an IntegrityError during commit, but the error handling is generic and might expose internals or leave the session in a bad state.

6. Reproduktion

1. Create user A.
2. Create user B.
3. Login as user A and update username to user B's username.
4. Observe the generic 400 error and potential session state issues.

7. Root-Cause-Analyse

Missing pre-commit uniqueness check for the new username.

8. Impact

- User-Impact: All users.
- Daten-Impact: Potential account interference or bad DB state.
- Security-Impact: Medium/High (Account takeover if constraints are misconfigured).

9. Fix-Richtung (kein Code, nur Strategie)

Add a check `get_user_by_name(db, user.username)` before updating `_user.username`. Also handle IntegrityError gracefully with a `db.rollback()`.

10. Test-Vorschlag

Test updating username to an already existing one and ensure it returns a clear 400/409 without breaking the DB session.
