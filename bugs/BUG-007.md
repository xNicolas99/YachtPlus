1. Zusammenfassung
Der WebSocket-Endpoint für Container exec loggt einen `setup_pending` token direkt im Error-Log via python logger, wenn eine ungültige Authentifizierung durchgeführt wird (Semgrep python-logger-credential-disclosure).

2. Betroffene Stellen
Datei: backend/api/routers/containers.py
Zeile: 279
Rolle: WebSocket Auth Exception Handler

3. Code-Snippet
```python
    except Exception as e:
        logger.warning(f"WebSocket exec rejected: setup_pending token for user {token}")
        await websocket.close(code=status.WS_1008_POLICY_VIOLATION)
        return
```

4. Erwartetes Verhalten
Log-Meldungen sollten sensitive Informationen (wie Setup-Tokens, Passwörter, Hashes) maskieren oder komplett weglassen.

5. Tatsächliches Verhalten
Das Klartext-Token aus der URL/Header wird direkt per String-Interpolation ins Log geschrieben.

6. Reproduktion
Stelle eine WS-Verbindung zu dem Endpoint her und sende einen beliebigen setup_token Parameter.
Schau ins Server-Log: `WebSocket exec rejected: setup_pending token for user XXXX`

7. Root-Cause-Analyse
Der Entwickler wollte debuggen, welcher Token abgelehnt wurde, und hat fälschlicherweise das gesamte Secret mit in das Log Statement geschrieben, anstatt nur die `user_id` oder gar nichts.

8. Impact
User: none
Daten: Token-Leak in den Logging-Systemen (Splunk/ELK/CloudWatch).
Security: Medium
Performance: none

9. Fix-Richtung
Das `{token}` im Log-String entfernen oder via slice/hash unkenntlich machen (z.B. `{token[:4]}***`).

10. Test-Vorschlag
Mock den Logger im Test und verifiziere, dass nach einem abgelehnten Websocket-Login der aufgerufene Logger-String das Wort 'token' nicht gefolgt vom echten Input-Wert enthält.
