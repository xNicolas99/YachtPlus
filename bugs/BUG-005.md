1. Zusammenfassung
Semgrep meldet einen hardcoded bcrypt hash im Code. Dieser wird laut Kommentar genutzt um Timing-Attacken bei unbekannten Benutzern zu verhindern (Dummy Hash).

2. Betroffene Stellen
Datei: backend/api/routers/users.py
Zeile: 34
Rolle: Dummy Hash Variable `_TIMING_DUMMY_BCRYPT_HASH`

3. Code-Snippet
```python
# Used to keep login response time roughly constant when the supplied username
# is unknown. bcrypt.checkpw still runs against this fixed digest, so an
# attacker can't distinguish "no such user" from "wrong password" via timing.
# This is NOT a real credential, decrypts to nothing, and is the only
# "hardcoded password" in the codebase. Tell static analysers explicitly.
# nosem: generic.secrets.security.detected-generic-secret.detected-generic-secret
# nosec: B105
_TIMING_DUMMY_BCRYPT_HASH = "$2b$12$EPB.k0Vz4T5lXl6uT9f9/eG0m7b7mG3aR4jPq4s0q3wY0r7U5/7qC"
```

4. Erwartetes Verhalten
Keine Hardcoded-Secrets im Code. Wenn Dummy-Hashes nötig sind, sollten sie als solche explizit validiert sein und keine Warning auslösen.

5. Tatsächliches Verhalten
Trotz `nosem` / `nosec` Kommentaren schlägt Semgrep `generic.secrets.security.detected-bcrypt-hash.detected-bcrypt-hash` an.

6. Reproduktion
`semgrep --config=auto --config=p/owasp-top-ten api/` laufen lassen.

7. Root-Cause-Analyse
Semgrep interpretiert bcrypt pattern Regex hart. Die `# nosem` Directive trifft nicht exakt die neuere Semgrep-Regel-ID.

8. Impact
Security: Low (False Positive, by design dummy)

9. Fix-Richtung
Semgrep-Ignore Kommentar anpassen von `# nosem: generic.secrets.security.detected-generic-secret.detected-generic-secret` zu `# nosem: generic.secrets.security.detected-bcrypt-hash.detected-bcrypt-hash` um die Pipeline zu befrieden.
